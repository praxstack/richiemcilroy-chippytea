# Engine architecture

Chippytea uses SwiftUI for the interface and a Rust library for authorization, discovery, classification, indexing, cleanup and reward accounting. The native bridge runs engine requests on a serial utility queue. Snapshot requests serialize the typed Rust snapshot directly into its JSON success envelope, without first allocating a generic JSON value tree. Other responses move their owned value into the envelope. Swift decodes the envelope and typed payload once on that queue, avoiding an intermediate object tree, re-encoding and main-actor decoding. The public Rust request API and JSON field semantics remain unchanged, including exact integer values, nulls and omitted fields. The response must contain a complete snapshot before existing sequence guards can apply it. Cancellation uses a separate atomic entry point so a queued request cannot delay it. Cleanup progress uses a separate utility queue and a small Rust mutex independent of the database, allowing progress reads while a mutation owns the store. AppKit supplies the tray/window, native folder grants, Quick Look and Trash; FSEvents supplies change notifications.

## Discovery and refresh

One utility worker traverses authorized local files using descriptor-relative, no-follow metadata. Outside Downloads and recognized artifacts, `Suggestions` uses libc's buffered directory reader to inspect names and types. Ordinary files need no full metadata or allocated pathname. Steps examine at most 256 names and check cancellation between entries. On macOS, full measurement uses validated 64 KiB `getattrlistbulk` records. A bounded shallow frontier prioritizes project boundaries; local depth-first overflow bounds memory. Recognized artifacts are measured as units, with bounded hard-link accounting and metadata fingerprints. The worker publishes batches of at most 64 candidates approximately every 100 ms.

Ordinary directory names are rejected by adapter dispatch before computing their parent and authorization prefix; supported artifact names still pass those checks before evidence reads. Child paths in the names and metadata readers reserve space for both components before copying, avoiding a parent allocation followed by growth. Construction retains `PathBuf::push` semantics and raw filesystem bytes. Neither optimization skips directory opens, coverage or identity validation.

A `DT_DIR` record is only a hint. Lexical exclusions and Keep boundaries run before `openat` with `O_DIRECTORY | O_NOFOLLOW`; `fstat` on that descriptor supplies authoritative metadata. Device, dataless and cloud checks precede traversal. The same descriptor survives classification and enters the frontier if descent is allowed, avoiding a separate pathname metadata lookup and reopen. `DT_UNKNOWN` retains no-follow metadata and the subsequent open-and-compare identity check. The depth limit remains a descent boundary after classification so artifacts at that boundary can still be recognized.

Directory readers initialize only when enumeration starts, after rechecking the captured identity. A names reader transfers descriptor ownership to `fdopendir` on success; bulk enumeration retains an untouched owned descriptor. Unsupported bulk enumeration restarts through a fresh open file description and verifies its identity. Lazy initialization removes unused prefetch for discarded directories; traversed directories still require their first read. Final identity checks remain in both paths. These mechanisms are documented in [REFERENCE-STUDY.md](REFERENCE-STUDY.md); performance claims require separate measurements.

Protected directory names are filtered before metadata in the names-first reader. An explicit `home` grant also omits its immediate Music, Pictures and Movies subtrees, without excluding unrelated project directories with those names. The same lexical scope policy runs before incremental probes and cleanup revalidation. Replayed excluded scopes reconcile their old derived results without filesystem access. A legacy `folder` Home grant can be atomically narrowed to `home` only when its physical identity matches and replacement is explicitly requested. That transaction invalidates old candidates and queues replacement discovery together. Native startup requests this narrowing after verifying the saved app identity and folder access, before any watcher or scan resumes.

The app uses `Suggestions` mode. It skips artifact contents once ownership, age or observed activity rules exclude them, and stops a measurement at the first unsafe or recently modified descendant. Progress reports entries actually examined, names examined without full metadata and artifact contents excluded from traversal. Byte totals cover measured entries, not all files encountered by name. A completed suggestion scan is not an exhaustive file inventory. Explicit `MetadataCoverage` mode retains full metadata traversal within the authorized policy boundaries, including deferred measurements of ineligible artifacts, for diagnostics and equivalent-workload benchmarks. Cleanup always requires a complete fingerprint.

Filesystem operations disable macOS dataless-file materialization on the calling thread and restore the previous policy on exit. This covers enumeration and intermediate path components as well as file reads. Existing cloud-name, flag, symlink, device and changed-directory checks remain in force; an enumeration failure never triggers a retry that downloads cloud data.

Project evidence reads pin the parent directory and return bytes together with the validated file identity. Metadata checks bracket opening and reading, and the original parent/path is checked again before accepting the capture. The fingerprint consumes that captured identity instead of reopening the path after parsing. Evidence is limited to 4 MiB per file; reads use chunks of at most 64 KiB with cancellation checks, including between ancestor opens. A swapped file or redirected parent invalidates the evidence rather than pairing old bytes with a new identity.

Scan-local caches reuse parsed npm and Bun ownership facts for shared workspace lockfiles. Each lookup receives currently validated captured bytes and their BLAKE3 digest; the existing content cache may supply unchanged bytes only after live identity checks. Manifests, workspace declarations, configuration and cleanup eligibility are rechecked. Inputs below 32 KiB bypass the facts caches. The npm cache retains at most eight entries and 8 MiB of heap capacity. The separate Bun cache retains at most eight entries and 1 MiB, containing only sorted workspace keys and optional names in packed buffers, not the dependency tree. Bun checks the current member manifest name on every lookup. These caps cover retained facts, not transient parsing or total process memory. Parsing preserves the original validation, comment/trailing-comma handling and duplicate-key semantics. Both formats validate the complete JSON document without constructing dependency-value trees. npm retains only object-valued package keys and version/dependency-shape markers; Bun retains version/package-shape markers and the workspace subtree. Input bytes, decoded keys, normalized Bun input and the workspace subtree still allocate transiently. An oversized result remains usable without retention. Cancellation is cooperative around normalization, parsing, hashing and compaction, including between discarded JSON values; allocation, individual JSON tokens, the retained workspace subtree and sorting are not individually preemptible. Cleanup revalidation uses the uncached path.

A separate pnpm cache reuses only packed, sorted importer keys from the same identity-validated captured bytes. It retains at most eight entries and 1 MiB of actual capacity including entry slots; inputs below 32 KiB bypass retention. Temporary borrowed-key collection is separately bounded to 1 MiB. The original limited pnpm grammar, error order, exact scalar bytes, duplicate-importer OR semantics and literal `.` root membership remain unchanged. A matching importer never skips later validation; this is not a general YAML validator. Oversized valid evidence answers normally without retention or eviction. Current workspace declarations, identities, configuration, evidence hashes and shared-store restrictions are still checked on each lookup, and cleanup uses the uncached parser. Cancellation is checked around parsing and compaction; the parser traversal and sorting are not individually preemptible. Neither capacity bound is a total process-memory limit.

A separate ancestor-manifest cache retains only the original ordered workspace-pattern strings from a fully validated `package.json`. It holds at most eight entries and 1 MiB of actual retained heap capacity, including unused entry and pattern slots. Inputs below 8 KiB take the original parsing branch directly. Inputs of at least 8 KiB use the digest of currently identity-validated captured bytes; each hit reruns membership matching for the current relative path. Successful false membership can retain facts, but errors, cancelled results and oversized lists are not retained; an oversized valid list does not evict useful entries. Full JSON recognition, workspace extraction and ordered matching keep their original error priority. Local manifests and Bun name checks are unchanged, as are current configuration, repository-boundary, evidence-hash and uncached cleanup checks. Cancellation is checked at cache entry and after successful evaluation; the full parse and pattern matching are not individually preemptible. The heap cap does not cover transient parsing or total process memory.

On macOS, absolute directory opens use `O_NOFOLLOW_ANY` to reject symlinks throughout one kernel path lookup. The original component-relative traversal remains for paths exceeding the syscall length limit, legacy `/.vol` paths and other platforms. Access and symlink failures never retry with weaker flags. Lexical path validation, cancellation, cloud-materialization policy, ancestor checks and the second evidence-parent validation remain in place.

In Suggestions mode, a recently modified `node_modules` or `target` boundary can be rejected before reading its ownership files: both supported adapters require seven quiet days, and additional evidence can only make the latest modification newer. This shortcut runs after scope and type checks, does not apply to the authorized root itself, and creates no candidate or ownership diagnostic. Exhaustive metadata mode remains unchanged.

Conditional names (`.venv`, `venv`, `.next`, `.nuxt`, `.turbo` and `.parcel-cache`) must first pass positive marker recognition before becoming pruning boundaries. A recently touched, unmarked folder with one of these names remains ordinary content: nested projects must still be discovered. Recognized artifacts containing a kept descendant are excluded before measurement or recent-file hint probing in both scan modes. Ordinary ancestors remain traversable so unrelated siblings are not hidden.

Keep overlap is checked in both directions when presenting, preparing and executing candidates. A kept parent excludes its descendants; a kept child also excludes an enclosing cleanup unit. SQLite uses literal path-component comparisons, not wildcard matching. Execution repeats this check under the store lock before candidate suppression or mutation. Keep is path-based, not a rename-tracking or in-flight cleanup cancellation mechanism. Rules version 8 schedules a one-time derived-index rebuild for these discovery corrections while preserving Keep, history and rewards.

Typed FSEvents preserve file type and whether a subtree needs reconciliation. Lexical filtering ignores protected paths, ordinary file writes outside Downloads and artifacts, and unrelated directory metadata noise. Ownership/configuration evidence and artifact changes still schedule scoped work; structural directory changes retain their subtree. Verified missing paths reconcile their exact index scope without climbing to a parent, so a deleted temporary file cannot trigger another Home traversal.

An exact, nonrecursive `Cargo.lock` file event refreshes the original item and the immediate sibling `target`, because only that project's Cargo evidence reads this lockfile. The original item remains part of discovery so Downloads, disappearance and file-to-directory replacements are reconciled. Manifest, configuration, unknown and recursive events retain broader coverage. An enclosing artifact or older enclosing index row takes precedence over this shortcut.

The exact lockfile path is the durable replay selector. One refresh generation captures only its subtree and the sibling target subtree; it never claims that their common parent was traversed. Pending parent/root work can subsume it, while events arriving after traversal begins remain queued. Cancellation and crash recovery replay the same selector, preserving prior incomplete coverage and the saved foreground result without adding a second journal format.

Before scanning the derived target path, the worker observes its exact directory-entry spelling through a pinned parent. It reads only names until the target matches, avoiding metadata probes of unrelated or protected siblings. A fresh reader and ancestry checks validate the same parent and target afterward. This also proves an empty lowercase target footprint when only `Target` exists on case-insensitive APFS, without traversing that alias. The scan's initial metadata must match the selected object. At most one target candidate, updated in place across progress batches, waits for validation before publication; traversal counters still progress. Both footprints share bounded hard-link accounting. The initial and final shallow name passes check cancellation and cleanup parking every 256 names. Any failed identity, ancestry or namespace check leaves the refresh incomplete and preserves old index rows.

One incremental startup operation returns either verified absence or metadata for the first entry, which the scanner consumes directly. A missing descendant can complete empty before any batch is published; a missing authorized root remains an error. Both outcomes pin a bounded chain of physical parents, check the actual opened grant, repeat the leaf lookup and verify ancestry, metadata, cloud state and cancellation. A renamed or replaced parent cannot supply a result through its detached descriptor. If the leaf disappears during verification, one fresh absence proof may establish an empty result; it never retries an error or substitution. Disappearance after traversal begins stays partial, preserving previously indexed rows. Successful narrow reconciliation never clears an unrelated prior coverage failure, and events received after its generation began remain pending.

An exact, nonrecursive file event for `.git/COMMIT_EDITMSG` is also irrelevant to discovery: commit text is not ownership or tracking evidence. Unknown and recursive events, Git index/configuration changes and mixed batches with artifact changes retain their normal scopes. Ignored events still durably advance the receipt cursor. The Swift bridge does not reload the index for an ignored-only acknowledgment or publish identical snapshots. Presentation changes and cleanup outcome edges are still processed.

The native watcher excludes Chippytea's private state directory at the stream and callback boundaries. A batch containing only state-file changes does not call back into the engine; otherwise persisting the event cursor could create another event indefinitely when Home contains the database. All watching stays stopped during access restoration or while a Home grant awaits confirmation, because any event can resume the engine's durable queue.

The callback also filters internal staging and recovery paths before retaining event payloads for the serial engine queue. It borrows callback entries individually and applies only a safe subset of Rust's root-relative policy: a `.chippytea-` component must precede any artifact or Git/Cargo evidence boundary, and every matching authorized root must permit exclusion. Explicit roots, ambiguous spelling and ordinary artifact rename events remain observable. Internal paths use one contiguous UTF-8 buffer and precomputed root bytes, avoiding repeated traversal of bridged strings. State-only batches stay silent. Loss flags still require reconciliation even when all paths were filtered.

Internal-only batches retain their maximum cursor without a path payload and share one flush scheduled after 100 ms on the existing serial FSEvents queue. Additional batches never extend that deadline. An ordinary callback immediately delivers its events with any pending cursor; a loss barrier discards the pending cursor and retains its original event ID, including a possible wrapped value. An intervening delivery leaves the original timer available for later internal batches. The timer clears its state before calling downstream and holds the helper weakly, so it neither retains an obsolete watcher nor polls while idle. Actual delivery remains subject to queue availability. This limits bookkeeping submissions during cleanup; it does not impose an absolute bound on the downstream task queue.

Relevant scopes enter SQLite before their receipt cursor advances. Pending scopes coalesce by ancestry; an event arriving during an active traversal remains independently pending. Moving a pending scope to active is transactional. Startup requeues active work; a rules-version change schedules derived-index rebuilding. Neither a long event batch nor pre-existing partial coverage silently expands an ordinary project change into a full Home pass. Genuinely lost event history requires reconciliation of the authorized roots.

Typed, nonrecursive file events inside a supported artifact can retain an optional original-file path. Suggestion discovery can also learn a path when an already required measurement observes a safe recent regular file and stops because the artifact is ineligible. The runtime pool holds at most 64 artifact hints and 64 KiB of root IDs and paths; it retains no filesystem observations or exclusion decisions. Event receipt performs only lexical checks, and hints become visible after the durable transaction commits.

At committed traversal start, Suggestions jobs copy this bounded pool and its revision. Full and scoped scans look up the exact artifact being discovered, discard stale hints locally and may learn a replacement. After successful journal finalization, only a complete, error-free, uncancelled scan may return its local pool, and only if the runtime revision still matches. Committed events, explicit Scan requests, grant changes and Keep changes invalidate older writeback, so a finishing scan cannot overwrite newer paths or undo a clear. Grant and Keep changes clear the runtime pool; explicit scans retain paths for fresh verification. Restart or eviction restores ordinary traversal. The local copy adds at most one more bounded pool, and measurement never takes the runtime lock to learn a path.

Suggestion discovery can use a hint only after the artifact passes ownership, age and activity checks. It verifies an owned, local, single-link regular file strictly inside the selected artifact through the original authorized root, without enumerating siblings. Pinned no-follow descriptors bind the artifact's full metadata and all ancestry through the final proof. A modification newer than the same quiet-period cutoff establishes only that the artifact is ineligible: the diagnostic has zero unmeasured totals and no fingerprint or cleanup permission. Keep and protected paths are excluded before probing. Missing, old, unsafe or changed observations fall back to ordinary measurement; cancellation remains partial. Metadata coverage and cleanup validation never use this shortcut.

Each bridge batch contains at most 512 scopes. Before touching the pending queue, a multi-scope batch canonicalizes and validates every path against one grant read inside the transaction. Sorting by path components removes duplicate scopes and descendants already covered by a batch ancestor. Surviving scopes return to their first-occurrence order before insertion, preserving FIFO with existing pending work. Invalid paths cannot disappear beneath a valid ancestor, and active scopes never subsume new events. Single-scope requests retain their direct path; failed batches roll back atomically.

Before starting a refresh generation, scope resolution and traversal use the same lexical artifact boundary: the outermost `node_modules` or `target` strictly below the authorized root. Raw persisted or unkeep paths therefore coalesce and reconcile the whole artifact even before it has an index row. Excluded paths retain their exact scope for zero-filesystem reconciliation; normalization never strips a protected suffix or widens to the grant itself. The original claimed path remains the acknowledgment and cancellation key.

Starting a claimed scope atomically validates its claim, records prior coverage, marks it incomplete, coalesces pre-traversal work and begins a refresh generation. A ticket binds that claim, scope and generation to finalization. Finishing atomically validates the ticket, reconciles candidates, saves statistics and coverage, requeues cancelled work and acknowledges the claim. Only complete coverage permits pruning. Cache invalidation follows a successful commit; a failed transaction leaves the claim and generation recoverable at restart. A claim cancelled before traversal uses a smaller atomic incomplete/requeue/acknowledgment operation.

The index keeps the last completed candidate while a new measurement is provisional. Each refresh records seen candidates in a disk-backed generation. Only a successfully completed scope removes absent old candidates. A partial pass retains older rows for review, with mandatory live revalidation before mutation. Coverage and event receipt are separate: an inaccessible area stays partial without causing endless full rescans. Explicit Scan requests a new full pass; a duplicate request while that foreground pass is active does not enqueue another.

Rust records the finite set of authorized roots selected by an explicit Scan. Its `foreground_scan` snapshot contains progress and completion for those full-root traversals, independently of background scopes in the durable queue. Completing the selected roots freezes these statistics even when filesystem events keep the worker running. Errors and cancellation remain incomplete across multiple roots. A new explicit request can begin during background maintenance; generation tickets prevent an older in-flight traversal from consuming it.

On the first worker launch after startup, already-pending full-root reconciliations receive the same finite tracking. This covers interrupted work and rule-version refreshes even if the watcher launches before Resume. It adds no scan work and does not replace a completed foreground result for later background events.

The last terminal foreground summary is saved separately from per-scope statistics and loaded once when the engine opens. It is historical presentation, never proof of current coverage or cleanup eligibility. A runtime fallback keeps it separate from live request tracking, so recovered full-root work still replaces it with active progress. A completed, cancelled or failed request saves once; ordinary event jobs neither rewrite the summary nor read it for snapshots. Cancellation persists at a worker boundary or before a new request replaces it on the utility queue, keeping the synchronous cancellation callback free of SQLite work.

An authorization revision binds each summary to its grants and classification rules. Successful grant changes and rule upgrades increment that revision and clear the saved summary in their existing transaction; stale requests cannot overwrite it. Snapshot capture and grant mutation share the runtime-to-store lock order, preventing a previous grant's summary from accompanying new roots. A failed summary save leaves candidate, coverage, queue and reward state unchanged, with an error reported for the unsaved presentation. Malformed optional cache content falls back to no historical summary; SQLite failures still propagate. Existing libraries cannot reconstruct a previous full scan from their latest tiny scope statistics and establish a summary on their next requested or already-pending full pass.

Swift uses that foreground status to keep the screen and completed statistics stable through later event refreshes. A pending request settles only after an authoritative snapshot started after Scan was accepted. Failed or skipped reads keep the request pending and polling active; sequence numbers reject older responses. Settled counts visibly say “Last scan”; a pending request says “Starting scan” until its authoritative progress arrives. A missing summary clears historical counts and says “No saved scan.” Raw cumulative or restored scope statistics cannot recreate a full-scan result after a grant change or restart. The existing control says Cancel for foreground discovery and Pause for background updates, with the same reserved geometry. An event cannot switch the empty view or move the list.

A newly acquired background worker waits up to 600 ms to combine queued events. Its monotonic deadline is captured before thread creation and never extended by later events. Scan and Resume advance a separate urgency generation and notify the condition variable, including when a worker already owns the queue. The generation preserves requests arriving before the worker starts waiting; a subsequent worker captures the new value and still batches normally. Capturing pending full-root recovery also bypasses an existing or newly created wait. Unkeep starts immediately when idle and retains an existing worker's batching. Cancellation and mutation pauses use the same wait mutex without polling; discovery remains parked until cleanup releases it. A lone background event can therefore appear later, while explicit scans and startup full-root work skip the batching delay. Native progress polling during active background work remains separate from this sleeping Rust worker.

The saved foreground count is separate from current settled coverage. A coverage attention flag changes only when maintenance settles, retaining its previous value during background work. Dismissed engine and snapshot-read errors stay dismissed while the same condition persists. Observed recovery or a new error re-arms that source; an accepted explicit scan can also re-arm its engine error once an authoritative post-request snapshot arrives. Stale reads do not re-arm errors or replace unrelated cleanup messages.

Raw snapshot delivery and SwiftUI invalidation are separate. A current-value publisher delivers every assigned snapshot before assignment, preserving observer timing for benchmarks and control hooks. The view model sends `objectWillChange` only when presentation-relevant fields differ. Raw statistics are omitted from that comparison, including when no foreground summary exists; all candidate, identity, authorization, wallet, history, error and control fields remain relevant. Applying every snapshot still derives settled coverage separately, and changes to that presentation publish independently. Thus hidden diagnostics do not repaint the view, while incomplete coverage and its recovery remain visible.

The bottom navigation receives the selected destination, pending-coin presence and displayed finding count as values. Its equatable boundary also compares the action model's identity, avoiding navigation reevaluation for unrelated progress updates while retaining current actions, accessibility labels and local hover state. Discovery computes its filtered, sorted findings once per body evaluation and shares that result across the list, empty state and toolbar count. The result is local to that evaluation, so filtering, selection and cleanup changes still use current candidates.

Native polling remembers each accepted request for an update, including requests arriving while a snapshot is in flight. An idle response ends polling only when that demand is unchanged since the read began. Otherwise the poller immediately reads again, so an older idle result cannot hide the completion of newer filesystem work. Active discovery retains the 150 ms cadence, cleanup still suspends ordinary reads, and no idle polling timer is added. This demand counter complements snapshot response ordering and the explicit Scan handoff; it does not replace either.

Snapshot decoding retains one successful response on the serial engine queue. Every poll still requests and copies a fresh Rust response. Only byte-for-byte equality with the complete retained envelope reuses its decoded value; changed responses decode normally. Errors clear the retained value and propagate immediately. A response above 1 MiB clears the cache and decodes without retention; that limit bounds serialized bytes, not the total decoded object memory. Returned snapshots are values, so callers cannot mutate the retained result. Request ordering, publication, cleanup outcomes and error recovery continue through the ordinary reload path, including cache hits.

## Cleanup while scanning

Review accepts only exact, completed, eligible indexed candidates with current authorization and Keep preferences. Permanent cleanup has one confirmation containing the selected items and removal consequences. Its optional “Don't ask again” preference takes effect only when deletion is confirmed; Settings can restore confirmation. With confirmation disabled, a deliberate cleanup click immediately submits the eligible selection through the same prepare, validation and execution path. It is restricted to eligible developer artifacts; personal Downloads use native Trash.

A mutation guard reserves cleanup before consuming the review token. The scanner parks at a cooperative checkpoint outside database/runtime locks, retaining its frontier and descriptors. Cleanup has its own cancellation flag. All exits, including expired tokens and unwinding, release the guard and resume discovery. Known mutated candidate IDs are tombstoned so an already buffered batch cannot resurrect them; affected scopes are queued for a fresh pass afterward.

Immediately before mutation, the engine verifies the grant, every physical parent, project ownership, Git tracking, observed activity and the complete metadata fingerprint. It exclusively stages the artifact beside its original path. Permanent removal captures each leaf into a private recovery directory and rechecks its identity before unlinking, avoiding deletion of a substituted name. Symlinks inside recognized developer artifacts are leaf objects: only their link payload participates in the fingerprint. Their targets are never opened or removed. Generated bundles are admitted only under that developer policy; cloud data, Photos libraries, Git metadata and shared stores retain conservative exclusions.

Regular hard links qualify only when a complete artifact measurement observes every name belonging to each linked inode. A bounded map counts names by device and inode, requiring identical complete metadata at every observation and a final count equal to `st_nlink`. It stores at most 131,072 groups; allocation failure, changing metadata, incomplete traversal or an outside alias excludes the artifact. Ordinary files allocate no group records. File counts retain all names, while logical and allocated bytes count each inode once. Downloads and hard-linked symlinks remain excluded. This is containment evidence for one measurement, so cleanup must establish it again.

The full revalidation streams file identities into a transactionally persisted manifest using cached statements. Ownership, activity, root and Git evidence are checked again after that walk. Any observer or validation failure rolls back the manifest. A separate staged fingerprint pass remains before removal. This shares one walk between validation and manifest creation without trusting stale scan results or dropping the checks around staging. Removal reads that committed manifest through one scoped read transaction and decodes identities directly from SQLite's borrowed text. Successful and failed exits release the read snapshot before accounting writes the receipt; partial removal retains the committed recovery evidence.

For an ordinary single-link regular file, the captured leaf's full metadata is checked before and immediately after a descriptor-relative private-allocation query. The query validates its own identity, timestamps, permissions, owner, flags and link count against that same capture. This replaces opening and closing each file solely to inspect allocation. Missing capability uses the existing descriptor path; a changed or malformed observation stops removal and preserves the captured leaf. The macOS query deliberately omits `ATTR_FILE_ALLOCSIZE`, whose single-file semantics differ from `stat`; both complete `stat` checks and the no-materialization guard remain. See Apple's [attribute API](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/man/man2/getattrlist.2) and [attribute implementation](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/vfs/vfs_attrlist.c).

The staged pass also rebuilds the internal-link proof. Removal keeps each group's original reviewed identity and exact current metadata. A captured alias must match both its manifest entry and that current state. After unlink, a retained descriptor verifies that the same inode lost exactly one link; only that verified transition updates the expected ctime for the next alias. Every group must reach zero links. A failure after unlink records a partial irreversible removal, preserves remaining paths and earns no credit. Private allocation is queried only for the final alias, and its descriptor closes before capacity sampling. These checks follow the filesystem's [link-count and metadata semantics](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/stat.2.html) and [final-link removal semantics](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/unlink.2.html); an internal link does not establish that APFS extents are private.

Confirmation immediately closes review, returns to the stash and marks the selected rows as in flight. The full chip flight, rising counter and ascending sound start with a transient estimate clearly marked as pending. Mute and Reduce Motion remain independent controls. Neither the preview nor its animation writes to the wallet or history, and Trash has no prospective chip reward.

The native model admits additional confirmed jobs while cleanup owns the mutation reservation. A bounded FIFO retains at most 100 waiting jobs, each with at most 100 exact reviewed candidates. Active and waiting jobs cannot overlap by candidate ID, path ancestry or file identity. Rust preparation runs only when a job reaches the head, so review tokens cannot expire in the queue and changed candidates fail without silent substitution. One job remains active through preparation, execution and an authoritative final snapshot; failed final reads hold the queue until reconciliation succeeds. Completion preserves any newer review and unsubmitted selection. Stop clears waiting jobs before cancelling the active operation. Closing the panel continues processing. Normal quit, including update installation, is refused while active or queued cleanup work remains. A forced process exit discards unsent queue intents rather than replaying destructive work on restart.

Each confirmed addition presents its own immediate feedback. The pending balance combines all outstanding eligible permanent bytes and applies the current fractional remainder once; Trash contributes no coin estimate. Each authoritative completion replaces that job's estimate with actual committed credit while retaining estimates for the remaining jobs. Starting the next queued job does not replay its animation. Actual collection waits for the queue to drain, then uses the same transactional ledger handoff.

One presentation envelope retains the attempt's identity, starting balance, estimated target and eventual verified target. A fast cleanup resolves that envelope without removing its initial animation. The resolved target uses all committed earned coins, including pending ones, so moving those coins into the collected wallet does not dip the counter. A changed target cancels interpolation toward the old estimate and settles quietly. The envelope retires only after presentation has finished and a successful collection or refreshed wallet backs its target; closing the window stops animated work.

A small ring in the masthead shows that cleanup is running. Its in-window details expose the real phase, entry counts and Stop control without blocking navigation. Counts restart between phases and items, so the ring indicates activity rather than inventing an overall percentage. Progress is throttled in Rust and read every 150 ms only during cleanup. Hidden windows and Reduce Motion stop the ring's animation; the preview's particle count and lifetime are bounded. Completion shows no informational popup; Activity retains the outcome and accounting details, including zero credit and Trash receipts.

Full snapshot requests pause for the operation and an authoritative final reload restores any failed or remaining candidates. The ring ends when execution returns, while a failed final read retains candidate suppression, pending feedback and the mutation reservation until reconciliation succeeds. Reopening or explicitly collecting requests another read; an unresolved preview does not create an idle retry timer. Partial failures still reconcile committed receipts and rewards. Actual collection remains a single-flight ledger request with one retained demand, so cleanup completion cannot be lost behind an older collection. That demand waits while another tab is active. An immediate collection suppresses the whole completion celebration, including its sound and counter restart. Requests capture a presentation generation: an older response may raise the confirmed collected balance, but cannot replace a newer cleanup's feedback. Completion does not force navigation away from another tab. Animation completion is bound to its own ID and cannot clear a newer presentation.

Standard linked Git worktrees are supported when the worktree and its repository metadata share the authorization and volume. The engine validates the `.git` pointer, common directory and reciprocal backpointer through owned physical paths, captures bounded index/configuration evidence, and checks it again around the tracking query and cleanup. Redirected or cloud-managed metadata, configuration includes, split/sparse indexes and unfamiliar formats remain excluded. Git metadata is safety evidence, never a cleanup target.

Native Trash returns its actual destination for recoverable history and earns no coins. Interrupted or partially failed mutations preserve receipts and recovery paths. Restart reconciles evidence; it never replays a destructive operation.

Restore permits historical ctime drift only for a directory root: native Trash metadata can settle after its callback returns. Device, inode, mode, size and modification time must still match, followed by the complete contents fingerprint and safety checks. Regular-file roots retain exact ctime because the root's ctime is omitted from staging fingerprints. The Trash parent is pinned before validation, and a second no-follow identity check includes the current ctime immediately before exclusive rename. A failed final check or cancellation leaves the operation recoverable in Trash.

## Storage credit and coins

SQLite WAL with full synchronous commits stores history, exclusive observation windows, per-operation allocations and the wallet. Estimated allocation is not a promise of reclaimable space. Accepted credit is bounded by eligible private allocation and observed available-space change; APFS sharing, snapshots and competing activity can reduce credit to zero. Fractional bytes carry forward at one coin per 100,000,000 credited bytes. Durable collection atomically transfers pending coins to the stash, so interruption cannot award them twice. The immediate visual estimate is independent of this transaction and is never restored as earned credit after a restart.

Each accounting window retains a descriptor on the original filesystem and resolves its storage domain once. Three capacity samples before and after cleanup use the highest pre-cleanup and lowest post-cleanup value. Competing writes therefore reduce recovery rather than invalidating it merely because capacity changed. The largest positive ambient rate observed within either sample group is reserved over the entire window.
