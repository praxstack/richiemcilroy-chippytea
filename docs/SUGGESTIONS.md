# Recommendation policy

chippytea indexes observations separately from the suggestions shown in the app. An indexed path is not a recommendation or permission to remove it. The public snapshot contains at most 500 completed, eligible suggestions; the coin screen uses the first three in the same order.

## What earns a place in the list

| Kind | Required local allocation | Quiet period | Evidence and consequence |
| --- | ---: | ---: | --- |
| User app cache | 50 MB | 30 days | A direct child of the authorized Home's `Library/Caches`. Known manager-owned stores are excluded. Close its app; recreation may require network access and slow the next launch. Review/Trash-only. |
| User log | 10 MB per file | 30 days | A regular file under the authorized Home's `Library/Logs`. Current sibling logs do not hide old rotated files. Logs may still be useful for troubleshooting. Review/Trash-only. |
| Crash / diagnostic report | 1 MB per file | 30 days | A regular file under `Library/Logs/DiagnosticReports`. Keep reports needed by support. Review/Trash-only. |
| Xcode DerivedData | 250 MB | 14 days | A direct project directory under `Library/Developer/Xcode/DerivedData`. Xcode and build tools must not be observed running. Rebuilding/reindexing is required; compiled products are removed. Review/Trash-only. |
| Cargo `target` | 100 MB | 7 days | A valid Cargo package/workspace and a standard target marker. No custom or ambiguous output ownership. Removing it requires recompilation and removes compiled binaries too. |
| npm / Yarn classic / Bun / supported pnpm `node_modules` | 100 MB | 7 days | A real package manifest and recognized lockfile; workspace members require declared membership and lock evidence. Dependencies need reinstalling; network access and compatible options may be required. |
| Python `.venv` / `venv` | 100 MB | 7 days | A direct regular `pyvenv.cfg` identifies the environment. Recreate it and reinstall packages before using the project. |
| Web build cache | 100 MB | 7 days | `.next`, `.nuxt`, `.turbo` or `.parcel-cache` beside the project's own regular `package.json`. Rebuilding is required. |
| Downloaded installer (`dmg`, `pkg`) | 20 MB | 14 days | A regular local file in an explicitly authorized Downloads scope. Its age does not establish that installation completed or that it is unwanted. Review/Trash-only. |
| Downloaded archive | 50 MB | 30 days | `zip`, `tar`, `gz`, `bz2`, `xz`, `7z`, `rar` or `iso`. No assumption that it was extracted or that another copy exists. Review/Trash-only. |
| Other large download | 100 MB | 30 days | Same location and local-file rules. Inspection and native Trash only; no permanent cleanup or coins. |
| Large personal file | 500 MB | 90 days | A known document, media or archive format in an authorized personal-file scope. Size and age make it worth reviewing, not disposable. Review/Trash-only. |

MB means 1,000,000 bytes. These thresholds are product heuristics, not platform guarantees. They use allocated size, not a sparse file's apparent length. Directory quiet periods use the newest modification time across descendants and ownership/configuration evidence, not just the directory's date. Future dates fail the quiet-period check. Modification dates are ranking evidence, not proof of disuse; access dates are not used to declare a file unused. Policy and SQL size thresholds are generated from the same rules.

Workspace declarations support literal path components, ordinary `*` within one component (such as `plugins/plugin-*`), whole-component `**`, explicit negations and root-only `.`. Wildcards do not include hidden components unless those components are explicitly named. Unsupported glob syntax remains a diagnostic. Declared membership still requires exact package-manager lock evidence and fresh ownership checks; it never overrides shared-store, activity or size restrictions. The pnpm interpretation follows its [package discovery](https://github.com/pnpm/pnpm/blob/v10.15.0/fs/find-packages/src/index.ts#L62) and [workspace discovery](https://github.com/pnpm/pnpm/blob/v10.15.0/workspace/find-packages/src/index.ts#L48) behavior.

An explicit Home grant enables its direct `Downloads`, `Desktop` and `Documents` subtrees for personal-file review. Downloads use their category-specific rules; Desktop/Documents use the 500 MB/90-day rule. An individually chosen generic folder also permits that large-personal-file rule, while a `projects` grant remains developer-only. A `downloads` grant or a selected folder itself named `Downloads` uses download rules; a child called `Downloads` inside a generic folder does not. Source/configuration files and hidden personal-file paths are not personal suggestions. Unfinished downloads and download bundles are excluded.

Home discovery probes only three fixed Library routes: `Library/Caches`, `Library/Logs` and `Library/Developer/Xcode/DerivedData`. It does not enumerate the rest of Library. Protected names and known manager-owned cache children are skipped before metadata in those route readers. Application Support, Preferences, Containers, device backups, Xcode Archives, DeviceSupport and simulators are not cleaner targets. Package-manager cleanup needs a dedicated manager-reported preview/prune integration; this version does not invoke one or guess an npm/pip/uv cache location.

Apple documents [Caches as regenerable, Application Support as potentially containing user data, and Logs as diagnostic files](https://developer.apple.com/library/archive/documentation/FileManagement/Conceptual/FileSystemProgrammingGuide/MacOSXDirectories/MacOSXDirectories.html). These are different evidence classes, not a blanket guarantee that Library can be erased. Apple's [storage interface](https://support.apple.com/en-sg/guide/mac-help/syspf5a64aa6/mac) surfaces large files and Downloads for review and describes System Data as macOS-managed. [Xcode's release notes](https://developer.apple.com/documentation/Xcode-Release-Notes/xcode-26-release-notes) document cleaning project DerivedData as a rebuild workaround, not permission to remove archives or projects. All newly added classes remain Trash-only.

Home discovery skips its immediate Music, Pictures and Movies folders before reading their metadata. A project such as `Projects/Music` is still supported. Photos and Music library bundles are protected wherever they appear; finding one inside an artifact disqualifies that artifact from cleanup. This keeps personal media outside the default cleanup scope and avoids unnecessary permission requests.

## What stays out

- Incomplete measurements, tiny artifacts, recently modified contents and unverified ownership.
- Observed activity or unknown process-activity results for developer artifacts, app caches and Xcode data. Git-tracked contents or failed Git checks exclude developer artifacts and large personal files. Installers, archives, other downloads, logs and reports are not Git/activity-checked.
- Cloud-managed or protected locations, shared stores, external or unverified hard links, nonstandard Cargo output, unverified package layouts and protected content. Within a validated developer artifact, generated `.app`, `.framework` and `.bundle` directories are supported. Symlinks are fingerprinted and removed as links; targets are never traversed, counted as recovered, or deleted. Strict traversal outside those artifacts retains its protected-bundle rules.
- Anything marked Keep. The scanner skips kept subtrees, and Include again requests a fresh scoped scan.

Regular hard links within a developer artifact qualify only after a complete measurement proves that every alias stays inside that artifact, with consistent identity, metadata and link counts. Bytes count once per inode. A link outside the artifact, a changing group or an exhausted proof limit excludes the entire artifact. Cleanup rechecks containment and verifies each link-count change during removal; only the final alias can contribute private allocation to the existing conservative recovery accounting. Hard-linked Downloads and hard-linked symlinks remain excluded.

Activity detection observes process working directories and executable paths. For app caches it lazily reads bounded, local app metadata and compares the cache name to exact running bundle identifiers, including outer apps of nested helpers. Developer-only scans do not perform those app-metadata reads. Cache ownership cannot always be identified, and activity checks cannot prove that no process has an arbitrary open file descriptor or command-line reference. Close relevant apps before moving caches to Trash. An app can continue writing through an open handle after the move; changed Trash contents can prevent automatic restore. Mutation also requires fresh identity, ownership and full metadata-fingerprint checks. This is a safety limit, not a claim that every app cache is idle.

Standard linked Git worktrees qualify when their project and repository metadata are inside the same authorized root and volume. The `.git` pointer, common directory, backpointer, index and configuration must be consistent, owned and local. Evidence reads are bounded, with index/configuration files limited to 4 MiB. Metadata symlinks, configuration includes, split/sparse or compressed indexes and unfamiliar layouts remain excluded. Tracked artifact contents are always excluded, including in supported worktrees.

## Ordering and freshness

Completed cache, log and build-artifact opportunities share the first group, then installers, then archives/other downloads, then large personal files. Within each group, larger allocated opportunities come first; the path breaks ties deterministically. The database maintains this order in a partial index and the native app preserves it as **Suggested first**. Caches & logs / Developer / Personal files filters and explicit size, age and name sorts are also available. Unsafe or provisional diagnostics cannot displace a useful suggestion.

Typed filesystem events refresh the affected cache/DerivedData unit, individual log/report or relevant personal file, as well as developer artifacts and ownership/configuration evidence. A new protected descendant invalidates its enclosing cache/build unit without probing the protected event path. Structural events on Library corridors expand only into the three allowed routes. Ordinary unrelated writes and directory metadata changes do not start scans. A short debounce and persistent ancestor coalescing combine work without widening after an arbitrary event count. Verified deleted scopes remove stale entries without scanning a parent. `MustScanSubDirs` and root-change events apply to their own paths; genuinely dropped history requires a full authorized-root reconciliation. An unrelated event does not expand because another part of Home was inaccessible.

The policy runs again immediately before cleanup. A change while a review is open requires a new review. No item is preselected. Only the original `cargo`, `node`, `venv` and `webcache` kinds can qualify for permanent deletion, explicit confirmation and conservative space accounting. Both native and engine operation boundaries enforce that allowlist independently of a saved eligibility flag. Native Trash is reversible while its contents remain unchanged, does not itself free storage and earns zero coins. Caches, logs, reports, DerivedData, downloads and personal files remain review/Trash-only. Completed findings stay reviewable during scanning; mutation parks the walker and resumes its saved frontier afterward.

A diagnostic can become old enough without generating a filesystem event. **Scan again** reevaluates age thresholds; there is no periodic background crawl just to promote old items. The event cursor records durable receipt, not successful coverage. Pending and active scopes survive interruptions; inaccessible areas remain visibly partial without replaying the whole event history. Cancel pauses automatic work until an explicit Scan or Resume.

## Explicit duplicate checking

**Check duplicate files** is a separate, opt-in action over completed, eligible indexed installers, archives, downloads and large personal files. It does not scan new locations or compare smaller/newer files absent from that index. Its query is independent of the ordinary 500-row visible page and can include an indexed path marked Keep as a keeper only. Existing age, size, local-file and authorization rules still apply.

Whole `(device, logical size)` buckets are considered in descending allocated-size priority. Selection inspects at most 1,024 buckets and admits at most 500 files, never a partial bucket. Verification uses 64 KiB buffers: first/middle/last samples, full BLAKE3 digests, then exact streamed equality. Exact comparisons batch up to 15 peers so each reference chunk is reused, without trusting hashes alone or loading whole files. Every member is revalidated before a complete hash group is published. It stops cooperatively after 64 GiB of payload reads or 60 seconds of verification; a blocked OS call is not preemptible. Skipped, limited, cancelled and complete results are distinct. No payload reads or background hashing are added to ordinary scans or idle refresh.

The report expires after 120 seconds and is invalidated by relevant raw events, scans, authorization/Keep changes and cleanup. It is an in-memory review aid, not persistent duplicate truth. The user must choose different files to keep and review; neither is selected automatically. A Keep-protected file cannot be the cleanup copy. Hard links, cloud-managed files, symlinks and changed identities cannot establish a match.

Duplicate cleanup always means **Move to Trash**, never permanent deletion or chips. Preparing a review reserves the retained copy against overlapping queued/pending cleanup. After the selected copy is staged beside its original path, cleanup compares it again with the retained file and validates the retained pathname immediately before Trash. A failed check or cancellation attempts an exclusive rollback; if restoration fails, the staged item is preserved and its location reported. These checks cannot prevent another app or user changing a file later; equal bytes do not prove that a path is unnecessary. Trash remains the reversible default, and APFS extent sharing means the displayed file sizes are not guaranteed recovered space.

Duplicate cancellation is separate from scan cancellation: it does not pause ordinary discovery, mark its coverage incomplete or cancel unrelated cleanup reviews. Duplicate discovery runs only during an explicit check, with progress polled during that operation. Cleanup separately rechecks the chosen pair.

## Coverage and tests

The app's `Suggestions` mode skips artifact contents already excluded by ownership, age or observed activity. Otherwise, measurement stops at the first unsafe or recently modified descendant. Personal-file discovery requests metadata only for known reviewable formats; ordinary source/configuration files retain the names-only path. No personal file contents or speculative duplicate hashes are read. Unvisited contents are not included in examined-entry or size counts. Progress reports examined entries and excluded artifact contents, and completion means suggestion discovery within those policy boundaries.

Explicit `MetadataCoverage` mode (`chippytea-cli scan <folder> --metadata-coverage`) retains exhaustive metadata traversal within the same authorization and protected-path boundaries. It defers ineligible artifacts behind useful discovery and drains that bounded queue before completion. Metadata-only diagnostic measurements never authorize cleanup. Equivalent traversal benchmarks use this mode or the raw traversal command; suggestion-mode counts must not be presented as exhaustive coverage.

Tests cover allocation versus sparse size, exact category cutoffs, indexed ordering, selective metadata reads, Library boundaries and event invalidation, fresh descendants/current sibling logs, authorization changes, forged permanent flags, Downloads boundaries, unfinished downloads, active processes, tracked files, Keep and path replacements. Duplicate tests cover whole-bucket admission, sampling false positives, exact comparison, no-follow readers, cancellation isolation, keeper reservations, expiration/event invalidation, and staged rollback when a keeper changes. Allocated and deliberately aged Home/report/duplicate fixtures exercise the engine review boundary. All test mutations are restricted to disposable fixtures. Performance claims require measured results, not only names-first source design.
